# SwiftDune on iOS

SwiftDune (the Swift reimplementation started by Christophe Buguet,
codingstyle/swift-dune, continued in the Codex "Continue Cryo Dune iOS port"
session) now builds for iPhone/iPad as well as macOS. Engine and game code are
shared; only the platform layer differs.

## Layout

| Path | What |
|---|---|
| `SwiftDune/Engine`, `SwiftDune/Game` | shared engine and scenes |
| `SwiftDune/Game/DuneGameApp.swift` | macOS entry point (AppKit window) |
| `SwiftDune/Platform/iOS/DuneIOSApp.swift` | iOS entry point (UIKit scene, touch, keys) |
| `SwiftDune.xcodeproj` | macOS game + editor (hand-maintained) |
| `project-ios.yml` → `SwiftDuneiOS.xcodeproj` | iOS target (XcodeGen, regenerated by the build script) |
| `scripts/build_ios.sh` | builds, ad-hoc signs and zips `builds/SwiftDune-ios-<stamp>.ipa` |

AppKit-only code sits behind `#if os(macOS)`. Files excluded from the iOS
target are listed in `project-ios.yml`.

## Building

```sh
brew install xcodegen      # once
scripts/build_ios.sh       # -> builds/SwiftDune-ios-<stamp>.ipa
```

The script builds by `-target`/`-sdk iphoneos26.5` rather than with a
`-destination`, because the "Any iOS Device" destination does not resolve on
this Mac. The asset catalog (macOS icon) is excluded: `actool` refuses to run
without an installed simulator runtime.

Install on the test phone (iPhone15,2, iOS 16.4.1) with TrollStore: serve the
IPA over HTTP and open `apple-magnifier://install?url=<ipa url>`.
`devicectl` cannot pair with this phone (CoreDevice error 1010), so there is no
cable install path.

## Input mapping

| Touch / key | Game input |
|---|---|
| tap on the picture | mouse click at that game pixel |
| finger held/dragged on the picture | mouse hover (menu highlight follows the finger) |
| swipe across the picture (≥ 20 % of its height) | arrow key in the swipe direction |
| ESC, ⏎, SPC buttons | Escape / Return / space (skip intro, close overlays) |
| BOOK, MAP, ORDR, RSLT, SIET, PROS | `b`, `m`, `o`, `r`, `f`, `p` (see `Game.onKey`) |
| ▲ ◀ ▶ ▼ buttons | arrow keys (rooms, desert walk, globe) |
| hardware keyboard | same keys as on the Mac |

## iOS-specific behaviour

- Audio: the session category is set to `.playback`. Without it the silent
  switch mutes everything — the ScummVM iOS build hit exactly this
  (fixed there by `0001-ios7-audio-session-playback.patch`).
- Logs: everything passed to `Logger.log` is also appended to
  `Documents/dune-ios.log`. `UIFileSharingEnabled` exposes the Documents
  folder in the Files app, so the log can be AirDropped back.
- Screenshots and `Resource.saveAs` dumps go to Documents on iOS (Downloads on
  macOS): `DuneEngine.outputDirectory`.
- Shaders: if the bundle has no `default.metallib`, `Renderer` compiles the
  same shader source at runtime. Keep `Renderer.shaderSource` and
  `Shaders.metal` identical.
- `exitProgram` shows an alert instead of calling `exit()` (iOS apps must not
  quit themselves).
- The game pauses when the app goes to the background and resumes on return.
- The input queue is locked: touches arrive on the main thread and the game
  loop drains the queue on a background thread (this was also a latent race on
  macOS).

## Knowledge carried over from the ScummVM engine work

The ScummVM engine (`Cryogenic/third_party/scummvm/engines/dune/`) is further
along; its `FINDINGS.md` is the reference for data layouts. Facts that matter
here:

- Both releases read the initial data segment from the executable
  (floppy `DUNEPRG.EXE` is LZEXE-packed), including the location, room and
  character tables.
- The room byte's high nibble is a sheet slot whose table differs per release:
  CD slot 0 = GENERIC, 6 = POR; floppy 0 = POR, 6 = SIET0, 8 = VILG, 9 = FORT.
- Saves use the original `DUNE21S?.SAV` (floppy) / `DUNE37S?.SAV` (CD) format.
- Clock and spice-density table: see `ORIGINAL_CLOCK_AND_LOCATION.md`.
- Reverse-engineering sources, in lookup order: madmoose/chani database,
  OpenRakis `DNCDPRG_RECENT.ASM`, madmoose/dune-rust (playability baseline),
  codingstyle/swift-dune (scene composition). Credit them per file.
